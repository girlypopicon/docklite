## Project Overview

DockLite is a Docker management and web hosting control panel. It provisions containers, manages nginx reverse proxies, handles SSL certificates, DNS records (Cloudflare), backups, and database containers — all from a web dashboard or terminal UI.

Three components:
1. **Go Agent** — Backend API server, Docker operations, nginx management, reverse proxy to GUI
2. **Next.js Web GUI** — Dashboard for all operations (sites, containers, databases, backups, DNS, SSL, users)
3. **Terminal UI (TUI)** — Standalone Bubble Tea client for remote agent management

## Build & Run Commands

```bash
# Production: use the CLI manager (PM2-based)
./docklite              # Interactive menu (first run = setup wizard)
./docklite start-all    # Start agent + GUI via PM2
./docklite stop         # Stop all
./docklite status       # Show status
./docklite restart      # Restart all
./docklite logs         # View logs

# Build individual components
make build-agent        # Go agent → bin/docklite-agent
make build-tui          # TUI client → bin/docklite-tui
make build-gui          # Next.js production build → webapp/.next/

# Development (hot reload)
make run-agent          # Agent on :9000 from source
make run-gui            # Next.js dev mode on :3000

# Tests
make test               # All tests (Go + webapp)
make test-go            # cd go-app && go test ./...
make test-web           # cd webapp && bun run test
make test-coverage      # Tests with coverage reports

# Installation
sudo bash install.sh    # Full install wizard (deps, build, configure, start)
sudo bash uninstall.sh  # Cleanup wizard (services, configs, optionally data)
```

## Architecture

```
Browser → nginx (:80) → Agent (:3000) → Docker Daemon
                             ↓
                        Next.js GUI (:3001-3002)
                             ↓
                        SQLite DB (data/docklite.db)
```

The agent is the central hub: it handles all `/api/*` requests directly and reverse-proxies everything else to the Next.js GUI. Nginx sits in front, routing port 80 to the agent and per-domain vhosts to site containers.

**Shared database**: Both agent (Go, via `modernc.org/sqlite`) and GUI (Node, via `better-sqlite3`) read/write the same SQLite file at `data/docklite.db`. Migrations live in `webapp/lib/migrations/` and auto-run on GUI startup.

**Process management**: PM2 manages `docklite-agent` and `docklite-gui` processes. Config stored in `.docklite.conf` (ports, tokens), ecosystem defined in `ecosystem.config.js` (both gitignored, generated by `./docklite`).

## Key Environment Variables

**Agent** (defined in `go-app/internal/config/config.go`):
- `LISTEN_ADDR` — default `:3000`
- `DATABASE_PATH` — default `data/docklite.db`
- `DOCKER_SOCKET_PATH` — default `unix:///var/run/docker.sock`
- `NEXTJS_URL` — GUI URL or `disabled` for headless mode
- `DOCKLITE_TOKEN` — bearer token for API auth

**GUI** (Next.js):
- `PORT`, `AGENT_URL`, `AGENT_TOKEN`, `SESSION_SECRET`, `DATABASE_PATH`

## Authentication

**Agent API**: Bearer token auth via `handlers/auth.go` `Auth()` middleware. Bootstrap token from `DOCKLITE_TOKEN` env var.

**GUI sessions**: iron-session with encrypted cookies. Three roles: `super_admin`, `admin`, `user`. Login at `webapp/app/api/auth/login/route.ts`.

**Default credentials**: `superadmin` / `password123`. Seeded in `webapp/lib/db.ts` `seedAdminUser()` on first startup when no admin exists.

## Nginx Management

The agent manages nginx configs via sudo commands (`go-app/internal/handlers/nginx.go`):
- `writeNginxSiteConfig()` — writes to `/etc/nginx/sites-available/` via `sudo tee`
- `enableNginxSite()` — symlinks to `/etc/nginx/sites-enabled/`
- `reloadNginx()` — runs `sudo nginx -t` then `sudo nginx -s reload`
- `setupNginxForDomain()` — orchestrates write → enable → reload for a site

Per-site vhost configs are generated automatically during site onboarding (`handlers/onboard.go`). The `docklite-default` catch-all config proxies port 80 → agent.

API endpoints: `GET/PUT /api/nginx/sites/{domain}`, `POST /api/nginx/test`, `POST /api/nginx/reload`. UI: `webapp/app/(dashboard)/network/NginxPanel.tsx`.

## File Management API

All site files live under `/var/www/sites/{username}/{domain}/` and are owned by `docklite:docklite`. **Do not write to these directories directly** — use the agent API, which runs as the `docklite` user.

Auth: all endpoints require `Authorization: Bearer {DOCKLITE_TOKEN}` header. The token is in `/opt/docklite/.docklite.conf`.

**List files:**
```
GET /api/files?path={username}/{domain}
```

**Read a file:**
```
GET /api/files/content?path={username}/{domain}/index.html
```

**Write/update a file:**
```
POST /api/files/content
{"path": "{username}/{domain}/index.html", "content": "<html>...</html>"}
```

**Create a file or folder:**
```
POST /api/files/create
{"basePath": "{username}/{domain}", "name": "style.css", "type": "file"}
{"basePath": "{username}/{domain}", "name": "assets", "type": "folder"}
```

**Delete a file or folder:**
```
POST /api/files/delete
{"path": "{username}/{domain}/old-file.html"}
```

**Rename:**
```
POST /api/files/rename
{"path": "{username}/{domain}/old.html", "new_name": "new.html"}
```

**Upload** (multipart): `POST /api/files/upload`
**Download**: `GET /api/files/download?path={username}/{domain}/file.txt`

All paths are relative to `/var/www/sites/`. Non-admin users can only access their own `{username}/` subtree.

## Site Transfer API

Transfer a site (files, container, nginx, DB record) to a different user:
```
POST /api/containers/{container_id}/transfer
{"new_user_id": 2}
```
Admin only. Copies files to the new user's directory, recreates the container with the correct mount, and updates nginx (preserving SSL config).

## Installation & Ownership

DockLite installs to `/opt/docklite`, owned entirely by `docklite:docklite`. Site files live at `/var/www/sites/`, also owned by `docklite:docklite`. Both the agent and GUI run as the `docklite` system user via PM2 (root daemon with `uid`/`gid` switching).

The `docklite` user needs Docker socket access via ACL:
```
sudo setfacl -m u:docklite:rw /var/run/docker.sock
```

PM2 is managed via `sudo pm2` since the daemon runs as root. The `docklite` CLI (`/usr/local/bin/docklite`) uses `sudo pm2` for start/stop operations.

## Adding Features

**New agent endpoint:**
1. Handler in `go-app/internal/handlers/[feature].go`
2. Route in `go-app/internal/api/router.go` wrapped with `handlers.Auth()`
3. Client call in `webapp/lib/agent-client.ts` if GUI needs it

**New GUI page:**
1. Page in `webapp/app/(dashboard)/[feature]/page.tsx`
2. API route in `webapp/app/api/[feature]/route.ts`
3. Check session via `getSession()` from `lib/auth.ts`

**New database table:**
1. Migration in `webapp/lib/migrations/[number]_description.ts` with `up`/`down` SQL
2. CRUD functions in `webapp/lib/db.ts`
3. Auto-applies on GUI startup
